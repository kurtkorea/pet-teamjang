## 4. 서버 사양 산정 근거

### 4.1 구성 원칙 — 온프레미스 + 클라우드 혼합

| 위치 | 담당 | 이유 |
|------|------|------|
| **온프레미스 (관제실)** | 영상 수집 · 녹화 · AI 검출 · 관제 웹 | 156대 상시 영상(약 312Mbps)을 클라우드로 올리면 회선 · 저장 비용이 커지고, 회선 장애 시 관제가 멈춥니다. |
| **클라우드** | 보호자 앱 · API · 라이브 중계 · 리포트 · 푸시 · 백업 | 외부 접속은 보호자 배정 객실만, 필요한 만큼만 중계합니다. 관제실 서버를 외부에 직접 노출하지 않습니다. |

참고로 클라우드 녹화형 CCTV 서비스는 카메라당 월 1~2만원 수준이라, 156대면 월 약 160~310만원이 회선비와 별도로 듭니다. 기준안의 녹화 스토리지(1,150만원)는 그 사용료 약 4~7개월분입니다.

### 4.2 녹화 스토리지

| 가정 | 값 |
|------|------|
| 평균 비트레이트 | 4MP · H.265 · 15fps · 스마트 코덱 · 정적 장면 위주 → **대당 약 2Mbps** |
| 전체 유입 | 156대 × 2Mbps = **약 312Mbps** |
| 일 저장량 | 약 3.4TB / 일 |
| 보존 기간 | **연속 녹화 30일** (분쟁 · 보안 대응) · 이벤트 클립은 별도 장기 보관 |
| 필요 용량 | 약 101TB |
| 구성 (기준) | 2U 12베이 서버 + 16TB 엔터프라이즈 HDD 12개 · RAID6 → **실사용 약 160TB** (여유 약 50%) |

보존 기간을 14일로 줄이면 필요 용량은 약 47TB로 줄어, 하한 구성(약 900만원)으로 충분합니다.

### 4.3 AI 서버 (검출 · 추적)

| 가정 | 값 |
|------|------|
| 분석 입력 | 서브스트림 640×360 · **5fps** × 156대 = 초당 약 780프레임 |
| 처리 능력 | YOLO 계열 경량 모델 + TensorRT 기준 고성능 GPU 1장이 초당 약 1,000프레임 이상 처리 |
| 구성 (기준) | GPU 서버 **2대** (각 1장) — 1대로 전량 처리 가능, 1대는 장애 대비 · 행동 분석 · 바이탈 확장 여유 |
| 소프트웨어 | 현재 PET-Aeye 스택(Rust 수집 · Python AI 워커 · Node API · React 관제)을 그대로 올립니다. |

### 4.4 앱 · DB 서버

관제 API · WebSocket · Redis · PostgreSQL을 관제실 서버 1대에 두고, 매일 백업 NAS와 클라우드로 백업합니다.

## 6. 5년 총비용 · 단위 원가

| 지표 | 산정 | 값 |
|------|------|------|
| 5년 총비용 | 구축 16,555 + 운영 425 × 60개월 | **약 42,055만원 (4.2억)** |
| 월 감가 (5년 정액) | 16,555 ÷ 60 | 약 276만원 / 월 |
| 객실 · 월 원가 | 42,055 ÷ (112실 × 60개월) | **약 6.3만원 / 실 · 월** |
| 1박당 원가 | 가동률 70% (월 21박) | **약 3,000원 / 박** |

- 안심 옵션 요금으로만 원가를 회수하려면 "1박당 요금 × 선택률 ≥ 3,000원"이어야 합니다. 예: 선택률 50%면 1박 6,000원 이상, 30%면 10,000원 이상(요금은 별도 설계 · VIP 객실 포함분은 제외).
- 외부 SaaS 판매(§5.4) 시에도 같은 구조로 "객실(카메라)당 월 구독" 원가 기준이 됩니다. 외부 고객은 대개 기존 카메라를 재사용하므로 구축비는 서버 · 네트워크 위주로 줄어듭니다.
