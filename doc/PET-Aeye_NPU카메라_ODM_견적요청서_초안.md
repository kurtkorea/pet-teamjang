## 1. 요청 개요

| 항목 | 내용 |

| 용도 | 펫호텔 객실·공용 · 펫 리조트 객실·공용 · 가정용 홈캠 |
| 핵심 | 카메라 **내부 NPU**에서 반려견 탐지·포즈·추적 추론 → 결과·이벤트만 서버 전송 |

### 3.1 기구 · 브라켓 전제 ODM (미니 웨지)

설치의 기본은 **일반 CCTV처럼 “본체 + 현장용 브라켓”** 입니다.  
가구(지붕)에 맞춘 **매립·특수 구멍 금형은 하지 않습니다.**  
본체는 어디서나 같고, **브라켓만** 오픈룸·케이지·홈에 맞게 바꿉니다.

#### 3.1.1 설계 원칙

| 원칙 | 내용 |
|------|------|
| 분리 | **Camera Body**(전자·렌즈·셔터·레이더) / **Mount Kit**(브라켓) 를 SKU·견적·물류에서 분리 |
| **벽 + 천장 겸용** | **동일 본체**로 **벽면 마운트와 천장(면) 마운트를 모두 지원** · 마운트 키트만 분기 |
| 교체 | 브라켓은 현장에 남기고 **본체만 탈착·교체·업그레이드** 가능 |
| 금형 | **기존 미니 웨지(하키퍽) 금형 우선** · 신규 금형은 셔터·RF 창 등 최소 수정 |
| 비목표 | 케이지 지붕 전용 매립 금형 · PTZ · 복도 천장 1대로 여러 칸 보기 |

#### 3.1.2 카메라 본체 (ODM) — 벽/천장 공용

| 항목 | 요구 |

| 실루엣 | **미니 웨지 / 하키퍽** · 납작 · 돌출 최소(손잡이·스틱형 금지) |

| 케이블 | **마운트 쪽(후면) 인입** · 벽·천장·브라켓 뒤로 숨김 · 늘어진 케이블 금지 |

## 4. 펌웨어 · AI · 연동 요구사항

### 4.1 역할 분담 (ODM ↔ 발주처)

원칙: **기기 안(펌웨어·기구·센서)·기기↔서버 프로토콜 구현은 ODM**,  
**정책·의미·화면·알림·비즈니스 연동은 발주처(PET-Aeye)**.  
앱이 레이더·칩을 직접 호출하지 않습니다. **카메라가 유일한 기기 게이트웨이**입니다.

#### 4.1.1 ODM이 할 일

| 영역 | 내용 |
|------|------|
| 하드웨어 | 보드·기구·렌즈·IR·PoE+Wi-Fi·물리 셔터·60GHz 레이더·온습도·촬영 LED · KC 등 인증 |
| NPU 런타임 | 발주처 제공 `.axmodel` 로드·추론 · 좌표·개체 ID·이벤트 원시 결과 생성 |
| 스트리밍 | RTSP(H.265 권장) · 로컬 버퍼 · 이벤트 클립 생성·업로드 |
| **기기 설정·제어 API** | 서버→기기 명령·설정 수신·적용·상태 회신 (**§4.1.3 필수**) |
| 텔레메트리 | 비전·레이더·모드·셔터·블러·온습도·링크 상태를 JSON/MQTT·HTTPS로 **발주처 서버만**에 전송 |
| OTA 에이전트 | 모델·펌웨어 다운로드·서명 검증·적용·롤백·결과 보고 (OTA **서버는 발주처**) |
| 차별 기능 실행 | 호텔/홈·외출·블러·폴백·LED·셔터 상태 등 **기기 동작** (§4.5) |
| 문서 | UART 맵 · JSON 스키마 · 설정/제어 API 스펙 · 오류 코드 · 샘플 로그 (DVT 전) |

#### 4.1.2 발주처(파우코리아 · PET-Aeye)가 할 일

| 영역 | 내용 |
|------|------|
| AI 모델 | 학습·변환 · `.axmodel` 제공 · 갱신 일정 |
| API·스키마 정의 | 텔레메트리·설정·제어·OTA 체크 URL·필드명 · 킥오프 시 확정 (ODM이 구현) |
| OTA 서버 | 패키지 호스팅 · 서명 키 · 카나리·롤백 정책 운영 |
| 관제·앱·PMS | 직원·보호자 UI · Stay 매핑 · 알림 문구 · 권한 |
| 정책 | 언제 호텔/홈·외출·블러·알림할지 · 임계값·근무 규칙 |
| 일일 요약 | 수면·활동 **카드·그래프·문구** (기기는 시계열 원천만) |
| 클라우드·온프레미스 | 수집 서버 · 저장 · LLM 등 — ODM 클라우드 강제 연동 **불가** |

#### 4.1.3 카메라 설정·제어 API — **ODM에 요청 (필수)**

**예, ODM에 요청해야 합니다.**  
앱·관제가 직접 칩을 만지지 않으므로, **설정·모드 전환은 전부 “발주처 서버 → 기기 API”** 로 갑니다.  
**스펙(필드·인증·에러)은 발주처가 정의하고, 기기 쪽 구현·문서·시연은 ODM**입니다.

| 구분 | 담당 |
|------|------|
| 설정 항목·JSON 스키마 · 인증 방식 | **발주처 정의** (킥오프 확정) |
| 기기에서 수신·적용·영속화·상태 보고 | **ODM 구현** |
| 앱·관제에서 “외출 켜기” 등 UI | **발주처** (기기로 명령을 중계) |

**최소 설정·제어 항목 (양방향 · 재부팅 없이 적용 권장)**

| 항목 | 예 |
|------|-----|
| 모드 | `mode=hotel` / `home` |
| 외출 | `away=on` / `off` (+ 셔터 연동) |
| 사람 블러 | `person_blur=on` / `off` |
| 레이더 | `radar=on` / `off` · 보고 주기 |
| 클립 | 길이·업로드 on/off · 폴백 보존 일수 |
| 영상 | 비트레이트·서브스트림 · (가능하면) LED on/off |
| OTA | 유휴 적용 시각 등 정책 파라미터 |
| 조회 | 현재 설정·버전·셔터·링크·온습도 **GET/상태 토픽** |

프로토콜은 MQTT(권장) 및/또는 HTTPS. 기기는 **발주처가 지정한 엔드포인트만** 사용합니다.  
시판 업체 전용 앱·클라우드에 묶인 설정 UI만 제공하고 문서화된 API가 없으면 **부적합**으로 봅니다.

### 4.3 OTA (필수 · 견적에 포함 여부 명시)

OTA(Over-The-Air)는 **계약·펌웨어 범위에 포함**해 주십시오. “미포함 / 포함” 단가를 나누어 제시해 주십시오.

| 항목 | 요구 |
|------|------|
| 모델 OTA | AI 모델 파일만 교체 (전체 OS 재설치 없이) |
| 펌웨어 OTA | OS·앱·에이전트 전체 업데이트 경로 |
| 프로토콜 | HTTPS 폴링 · 발주처가 정의하는 `/ota/check` · `/ota/report` (또는 ODM 제안 후 발주처 승인) |
| 서명 | 발주처(또는 지정) 키로 **서명된 패키지만** 설치 |
| 롤백 | 적용·부팅 실패 시 **이전 버전 자동 복귀** |
| 보고 | 성공/실패 · 현재 버전 · 기기 ID를 서버에 보고 |
| 적용 정책 | 유휴 시각 적용 등 설정 가능 |
| 인수 테스트 | EVT/DVT에서 **원격 카나리 배포·롤백 시연** 통과 후 양산 |

개발·PoC 단계의 USB/SSH 수동 반영과 **양산 OTA는 별도 마일스톤**으로 일정을 나눠 주십시오.

### 4.4 바이탈형 (주력 SKU) · 60GHz FMCW 레이더 · API

**본 건 주력은 바이탈형**이며, **1차 500대 · 2차 500대(합 1,000대) 전량 바이탈**입니다.  
기구·보드·펌웨어·KC(레이더 대역 포함)·§4.4 API를 **필수 범위**로 설계·견적해 주십시오.

바이탈은 **웰니스 참고값(비의료)** 이며, 진단·질병·의료기기 표현을 펌웨어·문서에 쓰지 않습니다.

#### 4.4.1 하드웨어

| 항목 | 요구 |
|------|------|
| 센서 | **60GHz급 FMCW mmWave** 모듈 (시판 모듈 또는 발주처 지정 BOM) |
| 연결 | SoC와 **UART 또는 SPI** · 전원은 카메라 보드에서 공급 |
| 기구 | 레이더용 RF 창(플라스틱) · 화각·IR과 간섭 최소화 · **§3.1 벽면 중고도·하향** 설치에 맞춤 |
| 기능 (기기) | **재실/부재** · **호흡 리듬·분당 호흡수(참고)** · 미동 수준 · (심박은 옵션·정확도 한계 명시) |
| 대상 | 근거리 실내(객실·홈). 다중 개체 분리는 필수 아님(1체 우선) |

#### 4.4.2 역할 분담 · 외부 API

레이더 칩을 앱이 직접 호출하지 않습니다. **카메라 펌웨어가 게이트웨이**가 되어 발주처 서버로 올립니다.

| 구분 | 담당 |
|------|------|
| 모듈 UART 프로토콜 | 레이더 모듈 공급사 스펙 |
| 파싱 · 비전 이벤트와 병합 · 전송 | **ODM 펌웨어** |
| 서버 수집 · Stay 매핑 · 알림 문구 · 앱 | **발주처 (PET-Aeye)** |
| ODM·모듈 업체 클라우드 강제 연동 | **불가** — 온프레미스·발주처 서버로만 전송 |

**전송 프로토콜 (발주처 정의 · ODM 구현):** MQTT 및/또는 HTTPS POST(주기·이벤트).  
페이로드는 JSON. 필드명은 킥오프 시 확정하며, 개념 예시는 다음과 같습니다.

```json
{
  "device_id": "string",
  "ts": "ISO-8601",
  "radar": {
    "presence": true,
    "breath_rpm": 18.5,
    "breath_confidence": 0.0,
    "motion_level": 0.0,
    "heart_bpm": null
  },
  "vision": {
    "pets": 0,
    "persons": 0
  }
}
```

| API 요구 | 내용 |
|----------|------|
| 주기 보고 | 설정 가능(예: 1~5초) · 유휴 시 주기 완화 가능 |
| 이벤트 | 재실 변화 · 호흡 이상 추세(임계값은 설정) · 장시간 미동 없음 등 |
| 설정 | §4.1.3 기기 설정·제어 API · 보고 주기 · 레이더 on/off · **사람 블러 on/off**(§4.4.3) |
| 원본 | 레이더 ADC 원시 대용량 상시 업로드 **금지**(연구 모드 별도 합의 시에만) |
| 문서 | UART 맵 · JSON 스키마 · 오류 코드 · 샘플 로그를 DVT 전 제공 |

#### 4.4.3 사람 블러 — **카메라 내장 기능 · 설정으로 on/off**

사람(`person`) ROI 블러/모자이크는 **모든 바이탈형 기기에 펌웨어로 넣습니다.**  
별도 SKU·별도 하드웨어가 아니라, **설정값 하나로 켜고 끄는 기능**입니다.

| 항목 | 요구 |
|------|------|
| 기능 | NPU로 `person` 검출 → 해당 ROI **실시간 블러/모자이크** 후 그 영상만 스트림·녹화에 사용 |
| **설정** | **`person_blur = on` / `off`** (기본값 협의 · 권장 기본 off 또는 on은 킥오프 시 확정) |
| 변경 경로 | 프로비저닝 · 발주처 서버 API · (가능하면) 로컬 설정. 재부팅 없이 적용 권장 |
| off 일 때 | 블러 없이 일반 스트림 (탐지·레이더·이벤트는 그대로) |
| on 일 때 | 블러 전 원본 프레임 **미저장·미전송** |
| JSON | 상태에 `person_blur: true/false` · (선택) `persons` 검출 수 포함 가능 |
| 인수 | DVT에서 on/off 전환 · 스트림 확인 필수 |

물리 렌즈 셔터(§3)와는 별개입니다. 촬영 OFF 시 레이더만 동작 가능 여부는 기본 사양에서 명시해 주십시오.

### 4.5 차별 기능 패키지 (펌웨어 · 기본 포함)

일반 IP캠·시판 펫캠과 구분하기 위한 **필수 차별 기능**입니다. 별도 SKU가 아니라 **모든 바이탈형에 포함**해 주십시오.  
역할은 §4.1과 동일합니다 — **기기 동작·설정 API 적용·상태 보고 = ODM**, **정책·알림·앱 문구 = 발주처**.

#### 4.5.1 모드 · 사생활

| 기능 | 요구 |
|------|------|
| **호텔 / 홈 모드** | 펌웨어 프로필 2종 이상. 예: `mode=hotel` (이벤트·셔터·블러 정책 중심) / `mode=home` (알림·양방향 음성 가능). 서버·프로비저닝으로 전환 · 재부팅 없이 적용 권장 |
| **외출 모드** | 서버/앱 신호로 `away=on` → 촬영·분석·(설정 시) 레이더 보고 활성. `away=off` → 촬영 OFF · **물리 셔터 닫힘** · 분석 중지(레이더만 남을지 설정). 상태 JSON 보고 |
| **사람 블러 on/off** | §4.4.3과 동일 · 모드별 기본값 설정 가능(예: hotel 기본 on) |

#### 4.5.2 전송 · 신뢰성

| 기능 | 요구 |
|------|------|
| **이벤트 클립** | 이상행동·바이탈/미동 이상 등 이벤트 시 **짧은 클립**(예: 5~30초, 설정)만 우선 업로드. 상시 원본 상시 업로드 금지(설정) |
| **회선 폴백** | 서버 연결 끊김 시 이벤트·레이더 요약·클립을 **microSD/eMMC에 보관** → 복구 후 재전송 · 용량·보존 일수 설정 |
| **PoE / Wi-Fi** | 둘 다 지원(§3). 가능하면 활성 링크·전환 상태를 JSON에 보고 |

#### 4.5.3 표시 · 환경 센서

| 기능 | 요구 |
|------|------|
| **촬영 중 LED** | 스트림/녹화 활성 시 점등(끄기 설정은 협의 · 호텔은 점등 권장) |

#### 4.5.4 일일 요약 (기기·서버 분담)

| 기능 | 요구 |
|------|------|
| **수면·활동 요약 원천** | 비전(자세·움직임) + 레이더(재실·호흡·미동) 시계열을 기기가 주기 보고. **하루 카드 문구·그래프는 발주처 서버**가 생성 |
