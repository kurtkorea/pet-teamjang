# 펫 장례 서비스 기능 맵 초안

## 1. 포지셔닝

| 구분 | 고팀장(사람) | 펫 장례(본 프로젝트) |
|------|--------------|----------------------|
| 주 사용자 | 장례지도사(상조팀장) | 펫장례 상담/의전 담당, 시설 운영자, (선택) 보호자 |
| 핵심 단위 | 장례 **행사** | 장례 **케이스(행사)** |
| 현장 | 장례식장 빈소 | 펫장례식장·화장장·자택/병원 픽업 |
| 일정 모델 | 다일(임종·입관·발인) + 종교 예식 | 당일~단기, 화장·추모식 중심 |
| 부가수익 | 화환·답례품·조의금 결제 | 추모용품·근조화·답례/기부·유골함 등 |

**한 줄:** 고팀장의 ‘현장 의전 OS’ 골격을 유지하되, 사람 의례·조의금·자격 중심 폐쇄형 구조를 덜어낸다.

## 2. 기능 맵 요약

| 우선순위 | 의미 | 예시 |
|----------|------|------|
| **필수(P0)** | 1차 출시에 없으면 장례 운영이 안 되는 기능 | 케이스 등록, 운구/화장 일정, 주문이력, 보호자 CRM |
| **선택(P1)** | 차별화·수익·운영 효율에 중요, 2차 이후 | 추모 알림장, 포인트 정산, 커뮤니티, B2B몰 |
| **제외/보류(P2−)** | 사람 장례 특화이거나 펫 시장 적합도 낮음 | 입관·상복·조의금 계좌 노출 플로우 |

## 3. 필수 (P0) — 바로 가져올 골격

### 3.1 케이스(행사) 관리 ← 고팀장 `01.행사`

| 기능 | 펫 장례 정의 | 비고 |
|------|--------------|------|
| 출동/접수 | 전화·앱·병원/호텔 연계 접수 | 펫호텔 연동 시 이관 접수 포함 |
| 케이스 등록 | 시설, 보호자, 반려동물, 일정 | 핵심 엔티티 |
| 상담·상품 안내 | 패키지/옵션 카탈로그 | 유골함, 관, 꽃, 추모용품 |
| 케이스 목록·검색 | 기간/상태/담당자 필터 | 현장 메인 화면 |
| 케이스 수정·취소 | 일정 변경, 노쇼, 병원 이관 | 상태머신 필요 |

**등록 시 필수 데이터(초안)**

- 시설: 펫장례식장/화장장명, 주소, 연락처, 룸/홀(있으면)
- 반려동물: 이름, 종/품종, 성별, 나이/추정나이, 체중(화장 요금 연동), 사진(선택)
- 보호자: 이름, 연락처, 관계(견주/가족 등)
- 일정: 픽업 시각, 입실/추모식, 화장, 유골 인도
- 메모: 특이사항(질병, 요청사항)

### 3.2 운구·이송 ← `02.긴급운구` (축소)

| 기능 | 펫 장례 정의 |
|------|----------------|
| 픽업 요청 | 자택 / 동물병원 / 펫호텔 → 화장장 |
| 차량·기사 배차 | 자체 차량 또는 제휴 운구 |
| 위치·상태 | 접수 → 배차 → 이동 → 도착 |

사람용 ‘앰뷸런스 긴급운구’ 복잡도보다 **예약형 픽업**이 기본. 긴급은 옵션.

### 3.3 공급망·주문·정산 ← `07.거래처/행사용품` + `01` 정산부

| 기능 | 펫 카테고리(초안) |
|------|---------------------|
| 내 거래처 | 운구, 꽃/근조, 관·수의, 유골함, 추모용품, (선택)도우미 |
| 주문 → 진행 알림 | 배송/배치/배차 상태 |
| 거래명세서 | 자동 생성·수정 |
| 보호자 영수증 | ‘장례 서비스 비용 영수증’ |
| 결제·장부 | 케이스별 매출/원가/마진, 월·년 합계 |

**제외하고 시작하는 카테고리:** 상복, 입관보조, 빈소 관리사(사람형).

### 3.4 보호자 CRM ← `06.고객관리`

| 기능 | 펫 장례 정의 |
|------|----------------|
| 케이스 이력 자동 적재 | 동물·보호자·상품·메모 |
| 전화 인입 시 이력 조회 | 번호 매칭(가능 시) |
| 추모일 알림 | 기일, (선택)생일·입양일·49일 |
| 수동/반자동 안부 메시지 | 템플릿 문자·알림톡 |

영업 목적이 아니라 **케어·재방문·호텔/상조 교차판매** 톤으로 설정.

### 3.5 계정·권한(최소) ← `11.회원가입` 축소

| 역할 | 설명 |
|------|------|
| 시설/의전 관리자 | 사업자, 직원 초대 |
| 상담·현장 담당 | 케이스 처리 |
| (선택) 보호자 | 일정 확인·결제·추모 페이지 열람 |

사람용 ‘장례지도사 자격증 필수 승인’은 **1차에서 강제하지 않음**. 제휴·사업자 확인 정도로 대체.

## 4. 선택 (P1) — 차별화·수익

### 4.1 추모 알림장·콘텐츠 ← `03.간단부고`

| 기능 | 적용 방식 |
|------|-----------|
| 온라인 추모 알림장 | 보호자가 지인에게 공유 (부고 용어 완화: ‘추모 안내’) |
| 일정 자동 반영 | 케이스 등록 정보 연동 |
| 추모 영상/슬라이드 | 사진 업로드 → 템플릿 영상 |
| 근조화·추모꽃 판매 링크 | 알림장 내 구매 CTA |
| 브랜드/시설 로고 | 제휴사·자사 로고 |

**보류:** 종교별 임종·입관·미사 세부 일정, 빈소 정광판 OCR.

### 4.2 답례·추모 굿즈 ← `04` + `05`

| 기능 | 적용 방식 |
|------|-----------|
| 답례/감사 메시지 링크 | 장례 종료 후 보호자에게 발송 |
| 답례품·추모굿즈 판매 | 수수료·포인트 정산 |
| 실시간 판매 알림 | 담당자 앱 알림 |
| (대안) 보호소 기부 | 조의금 대체 옵션 |

### 4.3 결제·포인트 ← `Hi, Dear PAY` / 마이페이지 포인트

| 기능 | 적용 방식 |
|------|-----------|
| 간편결제 | 보호자 결제, 거래처 결제 |
| 적립/충전 포인트 | 담당자·제휴 인센티브 |
| 현금화 | 정산 주기와 함께 2차 |

조의금 계좌 노출 방지 UX는 **펫 1차에서는 낮은 우선순위**. 기부/추모후원으로 대체 검토.

### 4.4 B2B 커머스 ← `08.고커머스`

| 기능 | 적용 방식 |
|------|-----------|
| 업종 소모품몰 | 위생용품, 운구용품, 포장재 등 |
| 공동구매 | 유골함·관 대량 구매 |
| 라이브/공구 | 커뮤니티와 묶을 때 |

시설·의전 네트워크가 일정 규모 이상일 때.

### 4.5 업종 커뮤니티 ← `09.커뮤니티`

| 기능 | 적용 방식 |
|------|-----------|
| 정보 공유 게시판 | 블라인드형 익명/반익명 |
| 시설 디렉터리 | 펫장례시설 조건·단가·후기 |
| 채용 | 상담원·운전기사 등 |

1차 제품 범위 밖. 플랫폼 확장 단계.

### 4.6 마이페이지·운영 ← `10.마이페이지`

포인트, 거래처 등록, 알림 설정, 고객센터, 공지 — P0 계정과 함께 **최소 세트만** 넣고, 나머지는 P1.

## 5. 제외 / 보류 (P2−)

| 고팀장 기능 | 제외 사유 | 재검토 조건 |
|-------------|-----------|-------------|
| 상복 주문 | 사람 전용 | — |

| 빈소 관리사(도우미) | 다일 빈소 전제 | 펫 빈소 상주 서비스 도입 시 |

| 조의금 계좌 + 범죄예방 플로우 | 펫 조문 문화에서 수요 낮음 | 대규모 공개 추모 시 |
| 장례지도사 자격 필수 가입 | 대상 직군 상이 | 협회·자격 연동 사업 시 |
| 사람 장례식장 조건표 | 도메인 불일치 | 펫시설 디렉터리로 대체(P1) |
| 스마트 가계부(계좌·카드 연동) | 범위 큼 | ERP 단계 |

## 7. 권장 릴리스 컷

### Phase 1 — 운영 MVP
- 케이스 접수·등록·상태
- 픽업/화장 일정
- 기본 상품·패키지 + 수동/반자동 주문
- 보호자 연락·메모 CRM
- 영수증·간단 정산
- 시설/담당자 계정

### Phase 2 — 경험·수익
- 추모 알림장 + 사진/영상
- 꽃·굿즈·유골함 온라인 판매·정산
- 추모일 알림·템플릿 메시지
- 거래처 앱 상태 공유

### Phase 3 — 플랫폼
- 제휴 네트워크·시설 디렉터리
- B2B몰/공구
- 커뮤니티
- 펫호텔·병원 연동 접수
- 포인트·현금화·고도 장부

## 8. 펫호텔과의 접점 (프로젝트 공간 맥락)

> 호텔·**peti** 기능 상세는 `펫호텔_기능맵_초안.md` (위탁 Stay·캠·리포트).

| 접점 | 설명 | 단계 |
|------|------|------|
| 임종·응급 이관 | 호텔 투숙 중 사망/위독 → 장례 케이스로 이관 | P0~P1 |
| 보호자 이력 공유 | 호텔 고객 = 장례 보호자 CRM 연계 · **Pet ID** | P1 |
| 교차 안내 | 장례 후 호텔/돌봄, 또는 고령 펫 보호자에게 사전 안내 | P1 |
| 사전 상조(예약) | 생전 등록·패키지 예약 (사람 상조형) | 별도 검토 |
| peti 이벤트 로그 | Stay 중 이상 이벤트 이력 → 이관 시 참고(선택) | P1~ |

## 9. 열린 결정 사항

1. **주 사용자:** 내부 의전팀만인가, 외부 제휴 시설까지 쓰는 B2B 플랫폼인가?
2. **보호자 앱:** 1차부터 제공할 것인가, 담당자 툴 + 링크형 페이지만인가?
3. **사전 상조(할부·회원제):** 사람 상조형 상품을 펫에 둘 것인가?
4. **결제:** 현장 카드/계좌만 vs 인앱 결제·포인트까지
5. **용어:** ‘부고’ ‘상조’를 쓸지, ‘추모·장례 서비스’로 완화할지
