## 0. 개요

**목적:** 파우코리아 펫호텔 영종의 오픈·운영 계획과, 자체 AI 관제 PET-Aeye의 호텔 적용 · SaaS 확장 계획을 한 문서로 정리합니다.

**범위:** 위탁형 펫호텔 1차(1동 4층 · 112실) · PET-Aeye 호텔 적용 · PET-Aeye SaaS  
**제외:** 동반숙박 · 장례 · 2차 개발(B1F · 나동) 상세

**전제:** 동물위탁관리업 등록 완료 · 1차 공사 완료 · PET-Aeye 관제 솔루션 운영

**구조:** 호텔 → PET-Aeye → SaaS는 하나의 흐름입니다.

| 층위 | 내용 | 역할 |
|------|------|------|
| 호텔 운영 | 112실 위탁 숙박 · 케어 · 스파 · 미용 · 샌딩 | 매출 · 현장 검증 |
| PET-Aeye | 보고(룸별 라이브) · 알리고(이상 행동) · 요약(CareReport) | 차별화 · 운영 효율 |
| SaaS | 위탁형 펫호텔 · 유치원 · 병원 입원실 · 훈련소 | 두 번째 매출원 |

호텔은 PET-Aeye의 첫 고객이고, PET-Aeye는 호텔의 차별점입니다.

### 1.4 서비스 메뉴

| 구분 | 내용 |

인스파이어 숏스테이 · 영종 생활권 데이케어는 같은 구성에서 기간만 다르게 운영합니다.

## PART 3. PET-Aeye 연계

### 3.1 PET-Aeye 기능

- **스태프용 관제:** 112실 룸 그리드 · 이벤트 타임라인, AI 검출 · 추적 · 행동 라벨, 이상 행동 알림 · PTZ 자동 추적 · 녹화
- **보호자용 안심:** 기간 한정 링크로 배정 룸 라이브, Stay 단위 일일 CareReport, 퇴실 후 하이라이트 클립
- **구성:** RTSP 수신 · 녹화 · YOLO + ByteTrack · 이벤트 DB · 실시간 WebSocket · 관리자 웹 · 보호자 웹

원 사업계획의 '24시간 CHECKING SYSTEM'을 사람의 순찰과 PET-Aeye가 함께 맡습니다.

#### 관리자 관제 화면

전 객실 라이브를 한 화면에서 보고, 각 객실에 개체·행동·신뢰도를 실시간으로 표시합니다. 확인이 필요한 객실은 강조되고, 급식·산책·알림 로그가 오른쪽에 쌓입니다.

![관리자 관제 화면](_mockups/out_admin_wall.png)

#### 스태프 앱 · 보호자 앱

스태프 앱은 확인 필요 알림을 맨 위에 두고, 객실 라이브와 AI 오버레이를 바로 보여 준 뒤 현장 확인/정상 처리를 한 번에 처리합니다. 보호자 앱은 배정된 객실만 실시간으로 열람하고, 오늘의 CareReport와 하이라이트 클립을 제공합니다. 안심 링크는 체크아웃까지 열리고 자동으로 만료됩니다.

## PART 4. SaaS 확장

### 4.1 원칙

영종은 PET-Aeye의 첫 고객이자 쇼룸입니다.  
흐름: 영종 운영 → 운영 데이터 → 제품 개선 → 운영 사례 → 외부 판매.  
외부 고객이 쓰는 기능은 영종 현장에서 먼저 씁니다.

### 4.2 타깃 고객

| 고객 | 필요 | 추천 패키지 |
|------|------|-------------|
| **위탁형 펫호텔 (핵심)** | 보호자 문의 응대 부담 · 야간 관제 인력 부족 | Plus |
| 유치원 · 데이케어 | 등원 중 보호자 확인 요구 · 놀이 / 사회화 기록 | Plus |
| 동물병원 입원실 | 입원견 상태 관찰 · 보호자 면회 대체 | Basic → Plus |
| 위탁 훈련소 | 장기 위탁 중 훈련 진행 공유 | Plus |

첫 판매 대상은 영종과 운영 방식이 같은 위탁형 펫호텔입니다.

### 4.3 패키지

| 패키지 | 대상 | 포함 기능 |
|--------|------|-----------|
| Basic — 스태프 관제 | 관제만 필요한 시설 | 카메라 등록 · 룸 매핑, 룸 그리드 라이브, AI 검출 · 이벤트 타임라인, 녹화 · 보관, 스태프 알림 |
| Plus — 보호자 안심 | 펫호텔 · 유치원 | Basic 전체 + Stay 관리, 보호자 기간 한정 링크, CareReport · 하이라이트, 시설 로고 · 이름 표시 |
| Pro — 다지점 · 연동 | 다지점 · 체인 | Plus 전체 + 다지점 통합 관제, 예약 시스템 API · 웹훅, 권한 · 열람 감사 로그, 전담 온보딩 |

**과금(안):** 객실(카메라) 수 기준 월 구독 + 설치 · 온보딩 1회 비용. 단가는 영종 운영 원가(영상 저장 · AI 연산 · 회선) 확인 후 정합니다.

### 4.4 제품 요건

| 요건 | 내용 |
|------|------|
| 멀티테넌트 · 권한 | 시설별 데이터 분리, 운영자 · 매니저 · 스태프 · 보호자 역할 |
| 온보딩 | 카메라 자동 검색(ONVIF), 룸 매핑 마법사, 설치 가이드 |
| 배포 | 클라우드 기본, 회선이 약한 시설은 현장 엣지 장비 |
| 과금 · 계측 | 카메라 · Stay 사용량 집계, 구독 결제 · 청구서 |
| 보안 · 개인정보 | 영상 열람 기록, 보존 기간 설정, 개인정보 처리위탁 계약 양식 |
| 운영 지원 | 카메라 끊김 감지, 원격 점검, 무중단 업데이트 |

S0(영종 내부 운영)에는 단일 시설로 쓰고, S1(파일럿)부터 멀티테넌트 구조로 전환합니다. 기능 ID 기준 상세는 `펫호텔_기능맵_초안.md` §5.4(H-TNT · H-API · H-BIL)에 이어 정리합니다.

### 4.5 로드맵

| 단계 | 시점 | 할 일 | 넘어가는 조건 |
|------|------|-------|----------------|
| S0 · 영종 내부 운영 | 오픈~6개월 | 전 객실 가동, 알림 규칙 · 리포트 다듬기, 운영 원가 측정 | 안정 가동 · 보호자 열람률 |
| S1 · 파일럿 | 6~12개월 | 외부 시설 2~3곳, 온보딩 도구 · 멀티테넌트, 운영 사례 정리 | 파일럿 유지 · 유료 의향 |
| S2 · 정식 판매 | 12개월~ | 요금제 확정, 설치 파트너 확보, 고객 지원 체계 | 유료 시설 수 · 이탈률 |
| S3 · 채널 확장 | 이후 | 예약 플랫폼 연동, 유치원 · 병원 패키지, 다지점 고객 | 파트너 유입 비중 |

S0 기간에는 호텔 운영을 우선합니다. SaaS 전용 기능 개발은 S1부터 시작합니다.

### 4.6 영업 채널

| 채널 | 방법 | 준비물 |
|------|------|--------|
| 직접 영업 | 수도권 · 공항 권역 펫호텔 방문, 영종 견학 · 라이브 데모 | 데모 계정 · 운영 사례 |
| 설치 파트너 | CCTV 시공 업체와 제휴, 설치 시 PET-Aeye 함께 제안 | 설치 가이드 · 파트너 수수료 |
| 업계 행사 | 반려동물 박람회 · 업계 단체 세미나 | 부스 데모 · 소개서 |
| 연동 제휴 | 예약 · 결제 플랫폼 연동, 앱 마켓 입점 | API 문서 · 연동 가이드 |

가장 강한 영업 도구는 영종 현장입니다. 보호자 동의를 받은 화면만 사용합니다.
